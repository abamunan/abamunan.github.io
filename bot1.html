Messenger to Telegram Bot: End-to-End Technical Blueprint

This document contains the complete technical architecture, codebases, configuration instructions, and cloud deployment steps to route messages from a Facebook Messenger Group to a Telegram Group for 0$ total cost.

Architecture & Division of Responsibilities

Because automated user accounts are outside Meta's official API framework, tasks are split strictly between human environment setup and AI automated processing engine execution.

Task Phase Description Executed By
Credentials & API Setup Telegram Bot token acquisition, Telegram Chat ID extraction, Messenger Thread ID resolution. Human Task
Session Authorization Extracting browser cookies (appstate.json) to authenticate as a Facebook user. Human Task
Core Message Engine MQTT continuous socket listening, event payload handling, attachments extraction, Sender Name resolution. AI Engine Code
Dispatch Engine Formatting markdown captions and executing HTTP API calls to Telegram server endpoints. AI Engine Code
Deployment & Hosting Repository initialization, pushing to GitHub, configuring environment variables on Koyeb/Render for 24/7 runtime. Human Task

Phase 1: Environment & Credential Setup Human Task

1. Telegram Bot & Group Configuration

  1. Open Telegram and search for @BotFather.
  2. Send command /newbot, follow prompts to choose a Name and Username.
  3. Save the generated HTTP API Token (e.g., 7123456789:AAF...).
  4. Create target Telegram Group, add your new Bot as a member, and grant it Admin Privileges.
  5. Add @raw_data_bot to the group to inspect payload data, locate "chat": {"id": -100XXXXXXXXXX}, copy this exact Chat ID including the minus sign, then kick @raw_data_bot.

2. Messenger Credentials Extraction

  1. Open target Facebook Messenger group in desktop browser (e.g., https://www.messenger.com/t/987654321098/).
  2. Copy the tail end numerical sequence (987654321098). This is your Messenger Thread ID.
  3. Install browser extension c3c-fbstate (or EditThisCookie) in Chrome.
  4. With active Facebook session open, click extension -> Export session state.
  5. Save output file as appstate.json.

File 2: index.js

const login = require("@dongdev/fca-unofficial");
const TelegramBot = require("node-telegram-bot-api");
const fs = require("fs");
const path = require("path");

// Environment configurations
const CONFIG = {
  TELEGRAM_TOKEN: process.env.TELEGRAM_TOKEN || "YOUR_TELEGRAM_BOT_TOKEN",
  TELEGRAM_CHAT_ID: process.env.TELEGRAM_CHAT_ID || "YOUR_TELEGRAM_GROUP_CHAT_ID",
  TARGET_FB_THREAD_ID: process.env.TARGET_FB_THREAD_ID || "YOUR_MESSENGER_THREAD_ID",
  APPSTATE_PATH: path.join(__dirname, "appstate.json")
};

// Validate runtime AppState presence
if (!fs.existsSync(CONFIG.APPSTATE_PATH)) {
  console.error("❌ Fatal Error: appstate.json missing from root execution context!");
  process.exit(1);
}

// Initialize Telegram Bot Instance
const tgBot = new TelegramBot(CONFIG.TELEGRAM_TOKEN, { polling: false });

// Read Facebook Cookie Credentials
const appState = JSON.parse(fs.readFileSync(CONFIG.APPSTATE_PATH, "utf8"));
const userNameCache = new Map();

/**
 * Resolves Sender ID to human-readable full name with memory caching
 */
async function getSenderName(api, senderID) {
  if (userNameCache.has(senderID)) {
    return userNameCache.get(senderID);
  }
  return new Promise((resolve) => {
    api.getUserInfo(senderID, (err, ret) => {
      if (err || !ret[senderID]) {
        resolve("Unknown User");
      } else {
        const name = ret[senderID].name || "Unknown User";
        userNameCache.set(senderID, name);
        resolve(name);
      }
    });
  });
}

// Main Messenger MQTT Socket Initialization
login({ appState }, (err, api) => {
  if (err) {
    console.error("❌ Auth Error: Facebook Session Invalid or Expired.", err);
    process.exit(1);
  }

  api.setOptions({
    listenEvents: true,
    selfListen: false,
    logLevel: "silent"
  });

  console.log("✅ Facebook Engine Online. Listening to Thread:", CONFIG.TARGET_FB_THREAD_ID);

  api.listenMqtt(async (err, message) => {
    if (err) {
      console.error("⚠️ MQTT Socket Error:", err);
      return;
    }

    // Filter incoming payload for target thread ID and valid message types
    if (message.threadID === CONFIG.TARGET_FB_THREAD_ID && message.type === "message") {
      try {
        const senderName = await getSenderName(api, message.senderID);
        const textContent = message.body || "";

        let formattedCaption = `👤 *${senderName}*\n`;
        if (textContent) {
          formattedCaption += `💬 ${textContent}`;
        }

        // Send Text-only payload
        if (textContent && (!message.attachments || message.attachments.length === 0)) {
          await tgBot.sendMessage(CONFIG.TELEGRAM_CHAT_ID, formattedCaption, { parse_mode: "Markdown" });
        }

        // Process attachments array (Photos, Videos, Audio, Documents)
        if (message.attachments && message.attachments.length > 0) {
          for (let i = 0; i < message.attachments.length; i++) {
            const att = message.attachments[i];
            const caption = i === 0 ? formattedCaption : "";

            if (att.type === "photo") {
              await tgBot.sendPhoto(CONFIG.TELEGRAM_CHAT_ID, att.largePreviewUrl || att.url, { caption, parse_mode: "Markdown" });
            } else if (att.type === "video") {
              await tgBot.sendVideo(CONFIG.TELEGRAM_CHAT_ID, att.url, { caption, parse_mode: "Markdown" });
            } else if (att.type === "audio") {
              await tgBot.sendVoice(CONFIG.TELEGRAM_CHAT_ID, att.url, { caption, parse_mode: "Markdown" });
            } else if (att.type === "file") {
              await tgBot.sendDocument(CONFIG.TELEGRAM_CHAT_ID, att.url, { caption, parse_mode: "Markdown" });
            }
          }
        }
      } catch (dispatchError) {
        console.error("❌ Forwarding Exception Failed:", dispatchError.message);
      }
    }
  });
});

Phase 3: Deployment & Maintenance Human Task

1. Local Testing

2. 24/7 Cloud Hosting Deployment (Free)

  1. Create a new Private GitHub Repository and push your files (Make sure NOT to make appstate.json public if repo is public).
  2. Sign up at Koyeb.com or Render.com.
  3. Connect your GitHub repository and select Node.js environment.
  4. Specify build command: npm install and start command: node index.js.
  5. Deploy instance. The cloud platform will run your bot continuous 24/7 without needing your PC to stay active.

3. Ongoing Maintenance Cycle

Because session tokens expire periodically due to Meta security updates, perform this routine every 1-3 months:

  • If bot stops receiving messages, re-extract fresh session cookies via Chrome extension.
  • Replace contents of appstate.json in your project folder/cloud environment and trigger app restart.

Context & Technical Decisions Summary

Here is the contextual flow and key technical decisions established in our chat:

  • Core Goal: You want to build a system that automatically forwards messages from a specific Facebook Messenger group to a Telegram group.
  • Feasibility & Constraints: We established that this is fully possible using open-source libraries (@dongdev/fca-unofficial for Messenger listening and node-telegram-bot-api for Telegram sending). Official Meta Graph APIs do not allow reading personal group messages, so browser cookies (appstate.json) are used instead.
  • Pricing & Cloud Execution: The entire project can be built and run 100% free of charge without paid APIs or paid hosting (using platforms like Koyeb or Render for 24/7 uptime without keeping your local PC powered on).
  • Division of Responsibilities:
    • AI Scope Generating the complete engine codebase (index.js, package.json), setting up media/text forwarding logic, sender name resolution, and exporting the setup documentation as a downloadable .md file.
    • Developer (Your) Scope Creating the Telegram Bot via @BotFather, getting the Telegram Group Chat ID, extracting your Facebook appstate.json cookies, and putting the files together to run or deploy.
